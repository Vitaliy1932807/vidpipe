# vidpipe

Короткая рабочая памятка на каждый день — [КАК-РАБОТАТЬ.md](КАК-РАБОТАТЬ.md). Здесь — подробности и обоснования.

Конвейер производства YouTube-роликов. Ставится один раз, работает в любой
папке, где лежит `prompt.md`.

```
prompt.md → script.md → voice.txt → voice.mp3 → subtitles.srt
                                                      ↓
                    thumbnail.txt ← script.md    shotlist.csv → flow_prompts.json → Flow
```

## Установка (Windows)

Распакуй архив куда угодно. Зайди в папку, где лежит `pyproject.toml`:

```powershell
cd G:\A\vidpipe\vidpipe      # ← путь, куда распаковал
dir pyproject.toml            # должен найтись; если нет — ты уровнем выше или ниже

pip install -e .
pip install faster-whisper    # если субтитры считаются локально
vidpipe init --global         # создаст %USERPROFILE%\.vidpipe с .env и промптами
notepad %USERPROFILE%\.vidpipe\.env
vidpipe check
```

ffmpeg ставить отдельно не нужно — он приезжает вместе с зависимостями
(`imageio-ffmpeg`). Если у тебя уже есть свой сборкой получше, пропиши путь
в `FFMPEG_BIN` внутри `.env`, он будет главнее.

Ключи прописываются один раз. Дальше они видны из любой папки.

## Работа

```powershell
mkdir C:\ролики\оборона-киева
cd C:\ролики\оборона-киева

vidpipe init -t "Оборона Киева 1941"   # создать ТЗ
notepad prompt.md                      # дописать обязательные факты и ограничения
vidpipe                                # прогнать весь конвейер
```

`vidpipe` без аргументов = `vidpipe run` со всеми шагами в текущей папке.

```powershell
vidpipe -s shotlist,flow -f     # пересобрать только хвост
vidpipe -s script -f            # перегенерить сценарий после правки prompt.md
vidpipe check                   # что откуда берётся, чего не хватает
vidpipe run -d C:\ролики\другой # работать в другой папке, не переходя в неё
```

Шаги идемпотентны: выход уже есть — шаг пропускается, `--force` перезаписывает.
Куски озвучки кэшируются в `.vidpipe/`, обрыв на 40-м из 50 не заставит платить
за первые 39 заново.

## Шаги

| Шаг | Вход → выход | Чем |
|---|---|---|
| `script` | `prompt.md` → `script.md` | Claude + `script_engine.md` |
| `review` | `script.md` → `review.md` | Claude-редактор, правит `script.md` |
| `clean` | `script.md` → `voice.txt` | regex: разметка, ремарки, таймкоды |
| `tts` | `voice.txt` → `voice.mp3` | Voicer |
| `srt` | `voice.mp3` → `subtitles.srt` | faster-whisper или whisper.cpp |
| `shotlist` | `srt` + `script.md` → `shotlist.csv` | Claude, сетка по 8 с |
| `flow` | `shotlist.csv` → `flow_prompts.json` | Claude + `assets.md` |
| `thumb` | `script.md` → `thumbnail.txt` | Claude: заголовки, обложка, теги |
| `assemble` | `clips/` + озвучка → `video.mp4` | ffmpeg по таймингам из `shotlist.csv` |

## Откуда берутся промпты

Два файла настраивают поведение — `script_engine.md` (методика сценария) и
`assets.md` (блоки `[STYLE]` / `[ENV]` / `[NEGATIVE]` для Flow). Ищутся по
цепочке, первое найденное побеждает:

1. `./имя.md` или `./prompts/имя.md` — этот конкретный ролик
2. `.vidpipe-channel/имя.md` — этот канал (см. ниже)
3. `~/.vidpipe/имя.md` — общее для всех проектов
4. встроенные в пакет — запасной вариант

`vidpipe check` показывает, какой уровень сработал. Чтобы у ролика был свой
стиль: `vidpipe init --style` положит копию `assets.md` рядом, правь её.

Так же и с `.env`: сначала `~/.vidpipe/.env`, поверх него `.env` канала, поверх
него `.env` из папки ролика. С `--dir ПУТЬ` папкой ролика считается ПУТЬ —
и канал, и `.env` берутся оттуда, а не из той папки, где ты стоишь.

## Каналы

Каналы нужны, когда на одной машине живёт несколько серий на разных языках.
Язык, темп речи, голос, методика и память серии у каждого свои — а ключи API
общие, они остаются в глобальном `.env`.

Канал — это папка с подпапкой `.vidpipe-channel`. Ролик находит свой канал
поиском вверх по дереву: от папки ролика к корню диска, первая найденная
`.vidpipe-channel` и есть его канал.

```powershell
mkdir C:\каналы\hindi-horror
cd C:\каналы\hindi-horror
vidpipe init --channel hindi-horror
notepad .vidpipe-channel\.env          # раскомментируй язык, темп речи, голос
```

В `.env` канала все настройки создаются **закомментированными**: свежий канал
ничего не меняет, пока ты сам не раскомментируешь строку. Так и задумано —
строка в канале перекрывает глобальную, а пустое значение (`KEY=`) перекрывает
её пустотой. Поэтому копии всего шаблона там нет: она стёрла бы ключи и
сбросила настройки whisper и сборки. Не нужна настройка — оставь её под
решёткой, канал возьмёт глобальную.

Получается такая раскладка:

```
C:\каналы\hindi-horror\
    .vidpipe-channel\      .env, script_engine.md, assets.md
    series.jsonl           журнал серии этого канала
    выпуск-01\             папка ролика: prompt.md, script.md, voice.mp3 ...
    выпуск-02\
```

Что обычно различается между каналами:

| переменная | хинди | русский | английский |
|---|---|---|---|
| `WORDS_PER_MIN` | 147 | 150 | 140 |
| `WHISPER_LANG` | hi | ru | en |
| `DEFAULT_LANG` | Hindi | русский | English |
| `VOICER_VOICE_ID` | свой | свой | свой |
| `FW_MODEL_SIZE` | large-v3 | medium | medium |

Канал можно завести и не сходя с места: `vidpipe init --channel ИМЯ --dir ПУТЬ`.
Если папка уже внутри другого канала, команда предупредит — вложенный канал
перекроет внешний для этой ветки дерева, включая журнал серии.

`vidpipe check` печатает имя канала, его путь и эти пять настроек — видно, в
каком канале ты стоишь и что он подставит. Если канала нет, так и пишет: работа
идёт на глобальном конфиге. Это законный режим — папки роликов, созданные до
появления каналов, работают как раньше.

## Модель: Claude, свой сервер или никакой

Шаги `script`, `review`, `shotlist`, `flow`, `thumb` зовут модель. Какую —
решает `LLM_PROVIDER`:

| значение | что это | ключ |
|---|---|---|
| `anthropic` | Claude по API (по умолчанию) | нужен `ANTHROPIC_API_KEY` |
| `openai` | любой OpenAI-совместимый сервер: LM Studio, vLLM, OpenRouter | по обстоятельствам |
| `none` | модели нет, эти тексты пишет человек | не нужен |

`vidpipe check` покажет провайдера, модель и адрес.

Локальная модель через Ollama здесь была и убрана. Замер на живом выпуске:
14B писала промпты для генератора кадров, которые приходилось переписывать
целиком, а приёмку сценария прошла с пятью находками, верными ноль. Она
заявила, что в тексте нет психологического разворота, хотя он есть и он лучшее
место сценария, и что финал заканчивается вопросом, хотя вопросительных знаков
в нём ноль. Уверенные ложные находки хуже молчания: они приучают не читать
приёмку.

Если локальная модель всё же нужна, поднимай её в LM Studio или vLLM и
подключай как `openai` по адресу `OPENAI_BASE_URL`. Таким серверам ключ не
нужен, и отдельный провайдер под это не требуется.

Режим `none` не аварийный, а рабочий. Механику конвейер считает сам: тайминги,
сетку сцен, сборку, приёмку, озвучку, распознавание. Думающие шаги в этом
режиме отдают заготовку с посчитанной частью и оставляют человеку то, что
требует решения.

Чего ждать по качеству: структурную работу — раскадровку и промпты Flow —
модель на 7B делает пригодно, схему CSV держит. Сценарий и заголовки на ней
заметно слабее: она сползает в общие слова и путает фактуру. Для текста
разумнее оставаться на Claude или писать руками.

## Методика каждого шага

Шаги берут инструкции из канала, а не носят их внутри себя. Это позволяет
держать в канале весь свой комплект промптов вместо копирования их в чат
руками:

| файл в канале | шаг | если файла нет |
|---|---|---|
| `research.md` | `research` — досье фактов | встроенный промпт |
| `script_engine.md` | `script` — сценарий | встроенная методика |
| `review_engine.md` | `review` — разбор черновика | `script_engine.md` |
| `packaging.md` | `thumb` — заголовки и обложки | встроенный промпт |
| `assets.md` | `flow` — блоки стиля | встроенные блоки |
| `bible.md` | `flow` — герои и предметы | без библии, с предупреждением |

Документ с методикой обычно хранится целиком: сверху пояснения «как
пользоваться», сам промпт выделен маркерами `=== ПОЧАТОК ПРОМТА ===` /
`=== КІНЕЦЬ ПРОМТА ===` (понимаются также `=== НАЧАЛО ПРОМТА ===` и
`=== START ===`). В модель уходит только блок между маркерами — иначе она
получает инструкцию, написанную для человека. Маркеры почти всегда упомянуты
и в самой инструкции, поэтому берётся самый длинный блок из всех пар, а не
первый попавшийся.

Шаг `research` собирает досье фактов в `dossier.md`, и `script` подмешивает
его в задание. Досье помечается как черновик: шаг не ходит в интернет, модель
отвечает по памяти, и даты с цифрами надо сверять по первоисточникам.

## Несколько языков

Один канал — один язык. Добавить язык значит завести канал, больше ничего:

```powershell
vidpipe init --channel en --lang en --dir "G:\English channel"
```

`--lang` подставляет то, что отличает язык: `DEFAULT_LANG` для промпта, темп
речи для расчёта объёма сценария, код для whisper и размер модели
распознавания. Готовые пресеты — `ru`, `en`, `hi`; новый добавляется одной
строкой в словарь `ЯЗЫКИ` в `cli.py`.

Дальше каналу нужны три вещи, и только они:

| файл | что задаёт |
|---|---|
| `.vidpipe-channel/.env` | язык, темп речи, голос, модель распознавания |
| `.vidpipe-channel/script_engine.md` | методика сценария под своего зрителя |
| `.vidpipe-channel/assets.md` | блоки стиля для генератора видео |

Методику нельзя просто перевести: правило «не объясняй свою страну зрителю»
требует своей фактуры на каждом языке. Русская методика говорит про вахтовку и
зимник, индийская — про dhaba и load-shedding; общим остаётся каркас.

Автоматизация список каналов у себя не держит:

```powershell
vidpipe channels
```

Команда показывает все каналы под `CHANNELS_ROOT` (несколько корней — через
`;`), их путь, число выпусков и номер следующего. Отсюда же берёт список
`tools/new-episode.ps1` — поэтому новый язык появляется в нём сам, без правки
скрипта:

```powershell
& "G:\A\vidpipe\vidpipe\tools\new-episode.ps1" -Channel en -Topic "The Fifth Milepost"
```

## Выпуск по шагам

Конвейер обрывается в двух местах, и `tools/new-episode.ps1` разделён по ним.

**Завести выпуск.** Создаёт папку и ТЗ, дальше текст пишет человек по методике
канала — скрипт его не сочиняет:

```powershell
& "G:\A\vidpipe\vidpipe\tools\new-episode.ps1" -Channel kak-bylo -Topic "Пожар в MGM Grand"
```

**Если писать некому.** Ключ `-Text` отдаёт досье, сценарий, разбор и
упаковку той модели, что настроена в `LLM_PROVIDER`. На локальной это черновик
под правку, а не готовый текст: методика канала весит тысячи знаков, и модель
на 14 миллиардов параметров держит её структуру, но не уровень.

```powershell
& "G:\A\vidpipe\vidpipe\tools\new-episode.ps1" -Channel kak-bylo -Episode "Пожар в MGM Grand" -Text
```

**Текст готов.** Озвучка, субтитры, раскадровка:

```powershell
& "G:\A\vidpipe\vidpipe\tools\new-episode.ps1" -Channel kak-bylo -Episode "Пожар в MGM Grand" -Produce
```

Шаги `script` и `review` сюда не входят намеренно: текст уже написан, и
переписывать его моделью нельзя.

`bible` и `flow` тоже не входят, и это решение по опыту, а не из осторожности.
Раскадровка это механика: код режет субтитры на сцены по таймингам. А библия
героев и промпты для генератора это решения, и на них локальная модель
ошибается дорого. На живом выпуске она списала идентификаторы героев из
примера в собственном задании, назвала чужой аэропорт и приписала героя
одиннадцати кадрам, где людей нет вовсе. Проверять её выходило дольше, чем
написать самому.

Нужны они всё же от модели:

```powershell
& "G:\A\vidpipe\vidpipe\tools\new-episode.ps1" -Channel kak-bylo -Episode "Пожар в MGM Grand" -Prompts
```

**Сценарий прочитан.** Шаги после сценария не начинаются, пока человек не
сказал, что текст прочитал:

```powershell
vidpipe ok
```

Причина простая: ошибка в тексте дешевеет только пока она в тексте. Дальше её
озвучивает платный голос, она уезжает в субтитры, из субтитров в раскадровку,
из раскадровки в промпты — и всплывает на готовом ролике, когда переделывать
нужно всё.

Подтверждение привязано к содержанию, а не к факту: помним отпечаток текста.
Правишь сценарий после проверки — подтверждение слетает само, иначе оно
означало бы «я читал» про текст, которого никто не читал. Перевод строк и
пустая строка в конце файла правкой не считаются: файл ездит между Windows и
git, и подтверждение не должно слетать на ровном месте.

**Музыка.** Кладётся файлом `music.mp3` рядом с каналом, и тогда она идёт
фоном во всех его выпусках. Отдельный выпуск может положить свой файл рядом с
собой или снять музыку совсем, задав `MUSIC_FILE` пустым.

Громкость фона ведёт сам голос. Ровный фон на одной громкости с диктором не
уживается: там, где голос тише, музыка лезет вперёд, а где громче — глохнет
сама. Поэтому диктор подключён боковой цепью: говорит — фон уходит вниз,
молчит — фон возвращается. Это то же, что делают руками на сведении.

Настройки — `MUSIC_GAIN_DB` (по умолчанию −20, насколько фон тише голоса),
`MUSIC_FADE_SEC` (подъём в начале и уход в конце), `MUSIC_DUCK_THRESHOLD` и
`MUSIC_DUCK_RATIO` (с какой громкости голоса фон уходит и насколько сильно).
Дорожка короче ролика зацикливается сама.

**Кадры по сценам.** Генератор нумерует клипы по порядку генерации, а сборка
читает первое число в имени файла. Пока сцены снимают подряд, это одно и то же.
Пропущена хоть одна — и всё дальше съезжает, молча:

```powershell
vidpipe clips
```

Команда сверяет имя каждого файла с промптом сцены и показывает, что чему
принадлежит; `--apply` переименовывает, прежние имена ложатся в
`карта-переименования.json` рядом. Недостающие сцены она делит на видео и
картинки: дорисовать и снять — разная работа.

Живой случай, ради которого это написано: в готовой папке файл `037` содержал
пятьдесят шестую сцену, остывший очаг из финала. Картинка разошлась бы с
голосом почти на весь ролик, и в логах этого не было бы видно. Поэтому приёмка
перед сборкой на таком разъезде теперь останавливается.

**Клипы готовы.** Сложены в `<выпуск>\clips` — собираем видео:

```powershell
& "G:\A\vidpipe\vidpipe\tools\new-episode.ps1" -Channel kak-bylo -Episode "Пожар в MGM Grand" -Assemble
```

Имя папки выпуска подстраивается под обычай канала: где выпуски пронумерованы
— берётся следующий номер, где названы по теме — название из темы. Явное
`-Episode` перекрывает и то и другое. Доступность модели проверяется до работы,
а не в середине: какая именно модель нужна, решает `LLM_PROVIDER`.

## Приёмка каждого шага

Проверка входа в конвейере была всегда: `preflight` не пускает шаг, если ему
нечем работать. Выход не смотрел никто, и брак ехал дальше как готовый
материал. Так в живом прогоне уехали 250 квадратных метров в библии вместо
пятидесяти пяти и промпт с фигурой в дверях там, где диктор говорит
«кто-то стоит».

Теперь после каждого шага работает `postflight`. Проверяет только код:
объём сценария, номера сцен, длительность против озвучки, числа библии против
текстов ролика, спойлеры в промптах, чужие идентификаторы героев, финал вне
мира ролика, финал на вопросе или призыве, запрещённые каналом знаки
(`SCRIPT_FORBID`). Находка уровня «стоп» не пускает результат дальше.

Смысловую приёмку моделью здесь пробовали и убрали. Замер на готовом сценарии
в 1263 слова: локальная модель на 14B думала 6 минут и выдала пять находок,
верных ноль. Она заявила, что нет психологического разворота, хотя он есть и
он лучшее место текста, и что финал заканчивается вопросом, хотя
вопросительных знаков в тексте ноль. Уверенные ложные находки хуже молчания:
они приучают не читать приёмку. Всё, что поддаётся счёту, считает код; смысл
остаётся за человеком.

Если нужно прогнать конвейер целиком и вычитать результат самому:

```powershell
vidpipe run --loose
```

## Одна команда на выпуск

Отдельные команды нужны, когда что-то пошло не так. В обычный день хватает
одной:

```powershell
vidpipe finish -d "путь\к\выпуску"
```

Делает по порядку: разложить клипы по сценам, снять водяной знак, собрать
фильм, прогнать аудит, назвать что осталось человеку.

Порядок не произвольный. Знак снимается **до** сборки: после сборки пришлось
бы чистить кэш посценных кусков и пересобирать заново. Сборка не идёт при
дырах: молча встал бы чужой кадр.

Первый запуск на незнакомой папке — с пробой. Она показывает, что было бы
сделано, и не трогает ничего:

```powershell
vidpipe finish -d "путь" --проба
```

Проба не для перестраховки. На девятом выпуске она показала «знак нашёлся бы
в 21 видео из 27» там, где выпуск чистый: `veo.найти` возвращает кандидата
всегда, а решает поле `уверенно`, и без этой проверки команда переписала бы
два десятка нормальных клипов. Теперь уверенность проверяется, и после правки
результат перепроверяется `остаток` — если знак остался, клип не подменяется.

Чего команда не делает: не рисует недостающие кадры. Она их называет и кладёт
рядом `промпты-НЕДОСТАЮЩИЕ.txt` — готовые промпты со стилем, окружением и
запретами, которые можно отправить в генератор не правя.

Ничего не пропадает: заменяемое уходит в `_варианты`, `_посторонние`,
`_до снятия знака`, `_до правки`.

## Проверка готового ролика

`postflight` смотрит текст и числа. Картинку он не видит, а брак чаще всего
именно там: водяной знак генератора в углу, надпись с датой на стене, два
разных плана под одним именем файла, кадр не от той сцены. Всё это ловилось
только глазами, и просмотр каждого выпуска целиком стоил дороже самой правки.

```powershell
vidpipe audit -d "путь\к\выпуску"
```

Отчёт короткий и текстовый. Проверяются четыре вещи, каждая из которых уже
находила настоящий брак:

**Сходимость.** Видео короче озвучки значит потерянный финал. В первом
выпуске раскладка выбросила паузы между кадрами, ролик оборвался на
шестнадцать секунд раньше и потерял всю развязку — по логам сборки этого не
было видно.

**Знак генератора.** Виден не на всех кадрах: фон под ним меняется, и одна
проба даёт 2 там, где на другой секунде 103. Берётся максимум по пяти пробам.
Порог грубый — яркий предмет в углу даёт ту же оценку, поэтому помеченные
кадры надо посмотреть глазами. Отчёт об этом честно предупреждает.

**Склейки внутри клипов.** Генератор иногда отдаёт под одним именем два
разных плана. Абсолютный порог тут не работает: вход предмета в кадр или
проезд камеры дают ту же разницу, что монтажный стык. Отличается форма — у
стыка это одиночный скачок на спокойном фоне. Детектор проверен на контроле:
настоящую склейку находит, ботинок, входящий в кадр, и проезд между руин не
помечает.

**Попадание кадра в свой промпт.** Ранг среди всех промптов ролика. Ловит
перепутанные кадры: сцена с мотоциклом заняла последнее место из семидесяти
пяти, и там действительно был не мотоцикл. Близкие по смыслу сцены
ранжируются низко сами по себе — смотреть надо только верх списка.

Быстрый режим без разбора клипов и без сверки промптов:

```powershell
vidpipe audit -d "путь" --fast
```

Шаг сверки промптов требует `pip install vidpipe[match]`; без этих пакетов он
молча пропускается. Разбор кадров требует `vidpipe[audit]`.

## Правка кадра: надписи и знак

Генератор пишет в кадре то, чего просить нельзя. Дата из блока `[ENV]`
выходит надписью на стене, на циферблате, на километровом столбе: строка
`July 1991` в описании места дала `JULY OF 19991` во всю стену. Отрицание
`no legible writing` этого не держит — положительная строка сильнее.

Первое лечение — убрать дату из `[ENV]` и держать эпоху только фразой
`No objects newer than ГОД`. Уже снятое правится так:

```powershell
vidpipe marks -d "путь" --знак "clips
-....mp4"
vidpipe marks -d "путь" --box 0.33,0.52,0.70,1.0 --контраст 0.12 --сила 5 "clips3_....jpeg"
```

Три приёма, выбор не вкусовой:

| приём | когда | почему |
|---|---|---|
| `--знак` | водяной знак генератора | знак вмешан в кадр, а не нарисован поверх: снимается накладкой, под ним остаётся настоящая картинка |
| `--приём сглаживание` | таблички, щиты, мелкий текст | буквы тонут, предмет остаётся резким; расфокус оставлял заметный мягкий блок |
| `--приём затирание` | надпись на ровной стене, крупный текст | заплатка берётся вплотную; сглаживание крупный текст сохраняет как свечение |

### Знак: почему накладка, а не заплатка

Генератор не рисует знак поверх кадра, он его вмешивает:
`кадр_со_знаком = α·белое + (1-α)·кадр`. Значит кадр возвращается точно:
`(кадр_со_знаком - α·255)/(1-α)`. Затирание тот же угол замазывает соседними
пикселями — на пробе 1280x720 ошибка в углу 2.7 против 0.5 у накладки, и
видно это не числом, а мазнёй поперёк границы цвета.

Раньше накладка тут оставляла призрак, и дело было не в приёме: альфа
снималась на глаз с одного кадра и занижалась, а место знака считалось по
долям кадра. Теперь профиль знака взят готовый — обмер настоящих выпусков Veo
(23x10, 68x30, 99x43 из
[gemini-watermark-remover](https://github.com/GargantuaX/gemini-watermark-remover)),
наш угол 1280x720 совпал с профилем 23x10 до пикселя. Место ищется
корреляцией по десяти пробам клипа, сила накладки считается из самого кадра
наклоном яркости по профилю знака.

Отката молча не бывает. Если знак не опознан, силу считать не из чего или
после правки остаток на месте — команда печатает причину и снимает знак
затиранием, как раньше. `--затиранием` заставляет так делать сразу, `--альфа`
задаёт силу накладки вручную.

Рамку ведёт шаблон самого предмета с подбором масштаба, поэтому наезд она
переживает. Общая модель движения кадра для этого не годится: на бликах и
дымке она возвращает неверное преобразование и об ошибке молчит — трижды
уводила заплатку мимо, прежде чем это выяснилось. Для наложенных подписей,
которые с камерой не едут, есть `--без-слежения`.

`--проба` кладёт результат рядом и не трогает исходник. Без неё оригинал
уходит в `_до правки`, а длина клипа сверяется: если разошлась, правка
отменяется.

## Озвучка

Озвучка идёт через **Voicer** (`voiceapi.csv666.ru`) — асинхронный API в три
шага: создать задачу, дождаться статуса `ending`, скачать mp3. Voicer работает
поверх ElevenLabs, поэтому `voice_id` и `model_id` — сущности ElevenLabs, но
свой ключ ElevenLabs не нужен, всё идёт через Voicer.

Весь сценарий уходит **одной задачей**. Жёсткого лимита длины у сервиса нет, он
сам режет текст на чанки, а минимальный заказ — 500 символов **за задачу**.
Дробить текст самому означало бы платить минималку за каждый кусок.

Задача кэшируется в `.vidpipe/voicer_task.json` по хэшу текста. Если прогон
оборвался на ожидании, повторный запуск дождётся ту же задачу вместо создания
новой платной копии. Текст изменился — хэш не совпадёт, будет новая задача.

Настройки в `.env`: `VOICER_API_KEY`, `VOICER_VOICE_ID`, модель, стабильность,
скорость. `vidpipe check` показывает остаток на балансе.

### Где взять голос

Голоса не добавляются в проект — берётся `voice_id` из библиотеки ElevenLabs
и вписывается в `.env`. Найти его можно так:

```powershell
vidpipe voices "russian male narrator" --lang ru --gender male
vidpipe voices --library standard --sort popular
vidpipe voices --voice-id y1adqrqs4jNaANXsIZnD     # точный поиск по id
```

Команда печатает `voice_id`, а для нестандартных голосов ещё и
`public_owner_id` — оба вписываются в `.env`. Есть три библиотеки:
`standard` (штатные ElevenLabs), `public` (общие, нужен `public_owner_id`),
`alternative` (для `VOICER_ENGINE=alt`).

Послушать голос перед выбором — на сайте библиотеки
`https://voiceapiru.csv666.ru`, там предпрослушка и фильтры. Ещё вариант —
собрать шаблон в Telegram-боте сервиса и подставить его UUID
в `VOICER_TEMPLATE_UUID` вместо отдельных настроек.

Найденный `public_owner_id` сохрани один раз: сервис просит не гонять поиск
повторно для того же голоса.

Тонкости, которые стоит знать:

- `VOICER_PUBLIC_OWNER_ID` нужен только для нестандартных голосов. Для голосов
  из штатной библиотеки поле оставляют пустым.
- `VOICER_TEMPLATE_UUID` (шаблон из Telegram-бота) и настройки голоса
  **взаимоисключающие** — если задать оба, сервис вернёт 422.
- `VOICER_ENGINE=alt` работает только на бесплатных голосах и тарифицируется
  с коэффициентом 1.5×.
- Одновременно допускается 5 активных задач.

## Субтитры

После распознавания считается покрытие: сколько секунд речи против длины
аудио. Меньше 70% или провал длиннее десяти секунд — значит часть записи
потеряна, и об этом печатается предупреждение. Тайминги при этом врут, а
раскадровка ложится мимо, поэтому пропускать такое молча нельзя.

Фильтр тишины (`FW_VAD`) выключен по умолчанию: на неанглийских языках он
вырезает куски настоящей речи.

По умолчанию `faster_whisper` — ставится через pip, компилировать нечего.
Если соберёшь whisper.cpp: `WHISPER_BACKEND=whisper_cpp` плюс пути в
`WHISPER_BIN` и `WHISPER_MODEL`. Конвертация в 16 кГц моно WAV делается сама —
это главная причина, по которой whisper.cpp обычно молча отдаёт пустой `.srt`.

## Почему сцены по 8 секунд

`SCENE_SEC=8` — родная длина клипа Veo. Сетка строится по реальным таймингам из
`.srt`, а не по расчёту «слов в минуту», поэтому картинка ложится на голос без
подгонки на монтаже. Хвост короче половины сцены склеивается с предыдущей.
