# ТЗ: многоканальность в vidpipe

Конвейер сейчас рассчитан на один канал. Нужно, чтобы на одной машине жили
несколько каналов на разных языках, каждый со своим голосом, методикой,
визуальным стилем и памятью серии.

## Что есть сейчас

Пакет `vidpipe` ставится один раз (`pip install -e`), команда работает в
текущей папке. Настройки берутся из двух мест, локальное перекрывает
глобальное:

* `<папка ролика>/.env`
* `\~/.vidpipe/.env` (путь переопределяется переменной `VIDPIPE\_HOME`)

Так же ищутся ресурсы — `script\_engine.md` (методика написания сценария) и
`assets.md` (блоки стиля для генератора видео). Порядок в
`Project.resource()`: папка ролика → `<папка>/prompts/` → глобальная →
встроенная в пакет.

Память серии (`series.jsonl`) лежит на уровень выше папки ролика — то есть
уже фактически привязана к каналу.

Шаги: `script`, `review`, `clean`, `tts`, `srt`, `shotlist`, `flow`,
`thumb`, `assemble`. Команды: `run`, `init`, `check`, `doctor`, `series`,
`voices`.

## Что нужно

### 1\. Уровень канала

Между папкой ролика и глобальным конфигом добавить слой канала. Приоритет:

&#x20;   папка ролика → канал → глобальный → встроенный


Канал определяется поиском вверх по дереву: от текущей папки поднимаемся к
корню, ищем подпапку `.vidpipe-channel`. Первая найденная — канал этого
ролика. Внутри неё лежат `.env`, `script\_engine.md`, `assets.md`.

Так же должна работать `series.jsonl`: искать её рядом с
`.vidpipe-channel`, а не просто на уровень выше папки ролика.

### 2\. Команда создания канала

&#x20;   vidpipe init --channel hindi-horror


Создаёт папку `.vidpipe-channel` в текущей директории, кладёт туда `.env`
из шаблона, копии `script\_engine.md` и `assets.md`, и пустой
`series.jsonl` рядом.

### 3\. Что показывать в check и doctor

`vidpipe check` уже печатает, откуда взят каждый ресурс (локальный,
глобальный, встроенный). Добавить уровень «канал» и строку с именем и путём
канала. Если канал не найден — сказать об этом явно, а не молча работать на
глобальных настройках.

### 4\. Настройки, которые различаются между каналами

Это то, ради чего всё затевается — по языкам они разные:

|переменная|хинди|русский|английский|
|-|-|-|-|
|`WORDS\_PER\_MIN`|147|150|140|
|`WHISPER\_LANG`|hi|ru|en|
|`DEFAULT\_LANG`|Hindi|русский|English|
|`VOICER\_VOICE\_ID`|свой|свой|свой|
|`FW\_MODEL\_SIZE`|large-v3|medium|medium|

Ключи API (`ANTHROPIC\_API\_KEY`, `VOICER\_API\_KEY`) остаются глобальными —
дублировать их по каналам не нужно.

## Чего НЕ надо менять

* Логику шагов. Они уже читают настройки через `env()` и ресурсы через
`project.resource()` — если поправить разрешение путей, шаги подхватят
канал сами.
* Формат `series.jsonl`, `shotlist.csv`, `beats.json`.
* Совместимость: если `.vidpipe-channel` нигде не найден, всё должно
работать как раньше, на глобальном конфиге. Существующие папки роликов
не должны сломаться.

## Как проверить

1. Создать два канала с разными `WORDS\_PER\_MIN` и `WHISPER\_LANG`.
2. В каждом создать папку ролика, запустить `vidpipe check` — убедиться,
что показывается правильный канал и его настройки.
3. Положить `script\_engine.md` в один из каналов, проверить, что `check`
показывает источник «канал», а не «глобальный».
4. Прогнать `vidpipe doctor` в папке без канала — должно работать
по-старому.
5. Убедиться, что `vidpipe series` в двух каналах показывает разные
журналы.

## Файлы, которых это касается

* `src/vidpipe/config.py` — `Project.resource()`, `load\_env()`, `GLOBAL\_DIR`
* `src/vidpipe/cli.py` — `cmd\_init`, `cmd\_check`
* `src/vidpipe/series.py` — `series\_path()`
* `src/vidpipe/assets/env.example` — комментарии про уровни конфига
* `README.md`

## Порядок работы

Сначала покажи план правок по файлам и дождись подтверждения. Не начинай
писать код, пока план не согласован — конвейер рабочий, в нём четыре
готовых ролика, и ломать разрешение путей вслепую нельзя.
